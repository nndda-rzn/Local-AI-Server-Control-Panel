1. Ringkasan Eksekutif
Local AI Server Control Panel adalah aplikasi web admin yang digunakan untuk mengelola server lokal pribadi melalui browser.
Produk ini memungkinkan admin melihat status server, mengelola container Docker, membaca log, melakukan restart service,
mengatur deployment project, mengelola konfigurasi AI inference, serta menghubungkan service lokal ke internet melalui
Cloudflare Tunnel.
Produk ini tidak bertujuan menggantikan platform seperti Portainer atau Coolify secara penuh pada versi awal. Fokus utamanya
adalah membuat panel yang sesuai dengan kebutuhan personal: deployment web, backend, database, dan model AI ringan seperti
YOLOv8/ONNX/PyTorch inference untuk demo, pengembangan, dan validasi sistem.
Target MVP: admin dapat login, melihat status server, melihat container, start/stop/restart container, membaca log container,
deploy project dari folder /server/apps, dan mengatur konfigurasi model AI dasar.
2. Konteks Server Saat Ini
Server dasar sudah dibangun sebagai server lokal berbasis virtual machine. Host menggunakan laptop lama dengan VMware
Workstation Pro, guest OS menggunakan Ubuntu Server, jaringan menggunakan NAT/VMnet8, Docker sudah menjadi runtime
deployment, dan Nginx container digunakan sebagai test service pada port 8080.
Komponen Status/Keterangan
Host Laptop lama/Windows dengan VMware Workstation Pro.
Guest OS Ubuntu Server tanpa desktop environment.
Network NAT/VMnet8 dengan adapter Ubuntu ens33.
Remote Access SSH dari Windows ke IP server.
Container Runtime Docker dan Docker Compose.
Service Test Nginx container, mapping 8080:80.
Struktur Folder /server/apps, /server/data, /server/backup.
Online Access Direncanakan melalui Cloudflare Tunnel.

3. Problem Statement
Pengelolaan server lokal melalui terminal cukup fleksibel, tetapi tidak ideal ketika jumlah service bertambah. Admin harus
mengingat command Docker, path project, konfigurasi environment, port mapping, dan log masing-masing service. Untuk project
web + AI, kebutuhan operasional menjadi lebih kompleks karena terdapat frontend, backend, database, model AI, file model,
konfigurasi threshold, serta hasil prediksi.
Masalah utama
Monitoring container masih dilakukan manual melalui docker ps, docker logs, dan docker compose.
Restart service dan deployment project masih mengandalkan akses SSH.
Konfigurasi AI model seperti path model, confidence threshold, dan device belum memiliki UI.
Riwayat deployment dan log perubahan belum terdokumentasi otomatis.
Akses publik via tunnel perlu dikelola dengan rapi agar tidak membuka service sensitif.

diizinkan.

Menyediakan log viewer dan audit aktivitas admin.

Non-Goals
Bukan pengganti penuh Kubernetes dashboard.
Bukan multi-tenant cloud platform untuk publik besar.

Tidak membuka database/SSH langsung ke internet.
Tidak dirancang untuk training AI berat.
Tidak menjadi sistem billing atau hosting komersial.

14. Security Requirement
Prinsip utama: panel ini mengontrol server. Jangan menyediakan terminal bebas, jangan expose database, jangan expose
SSH, dan jangan menjalankan command dari input user tanpa whitelist.
Area Requirement Keamanan
Authentication Password wajib hash, login rate limit, session expiration.
Authorization Role owner/admin/viewer; aksi destruktif hanya owner/admin.
Docker Socket Akses /var/run/docker.sock hanya untuk backend panel; endpoint harus ketat.
Command ExecutionGunakan whitelist command dan whitelist path.
Project Path Hanya boleh mengakses /server/apps, /server/data, dan path yang disetujui.
Upload Model Validasi ekstensi, ukuran file, lokasi penyimpanan, dan nama file.
Cloudflare Panel admin sebaiknya dilindungi Cloudflare Access atau minimal auth internal kuat.
Secrets Jangan tampilkan token/API key secara penuh di UI.
Audit Catat semua aksi sensitif.

sebagai service API terpisah. Panel hanya mengatur konfigurasi, memantau status, dan memicu restart service jika diperlukan.

    /sqlite
    /postgres

services:
  panel-frontend:
    build: ./frontend
    ports:
      - "3000:80"
    restart: unless-stopped
  panel-backend:
    build: ./backend
    ports:
      - "5000:5000"
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock
      - /server/apps:/server/apps
      - /server/data:/server/data
      - /server/backup:/server/backup
    environment:
      - NODE_ENV=production
      - JWT_SECRET=${JWT_SECRET}
      - ALLOWED_PROJECT_ROOT=/server/apps
    restart: unless-stopped
